- [ ] Akses Cloudflare (secret Worker) dan Supabase (jika diperlukan)

### C. Windows signing

1. [ ] Terbitkan sertifikat (OV/EV/cloud HSM).
2. [ ] Tambahkan konfigurasi signing ke `src-tauri/tauri.conf.json`:
   - OV/PFX: `bundle.windows.certificateThumbprint`, `digestAlgorithm = "sha256"`, `timestampUrl`.
   - Cloud HSM: `bundle.windows.signCommand` sesuai vendor.
3. [ ] Build: `npm run tauri build`
4. [ ] Verifikasi MSI:
   ```powershell
   signtool verify /pa /v "src-tauri\target\release\bundle\msi\Gerbang Edukasi_0.1.0_x64_en-US.msi"
   ```
5. [ ] Verifikasi NSIS:
   ```powershell
   signtool verify /pa /v "src-tauri\target\release\bundle\nsis\Gerbang Edukasi_0.1.0_x64-setup.exe"
   ```
6. [ ] Cek status di Windows 11 bersih:
   ```powershell
   Get-AuthenticodeSignature "path\ke\installer.exe" | Format-List
   ```
7. [ ] Catat SHA-256 installer untuk release notes.

### D. Updater (jika diaktifkan)

1. [ ] Generate kunci: `npm run tauri signer generate -- -w %USERPROFILE%\.tauri\gerbang.key`
2. [ ] Simpan private key di secret manager; **jangan commit**.
3. [ ] Isi `plugins.updater.pubkey` + endpoint update di `tauri.conf.json`.
4. [ ] Tanda tangani artifact dan uji update dari versi lama.

### E. Android signing

1. [ ] Buat keystore (simpan di secret manager):
   ```bash
   keytool -genkeypair -v -keystore gerbang-release.keystore \
     -alias gerbang -keyalg RSA -keysize 4096 -validity 10000
   ```
2. [ ] Tambahkan `signingConfigs.release` di `src-tauri/gen/android/app/build.gradle.kts` yang membaca `keystore.properties`/environment (jangan commit kredensial).
3. [ ] Build release: `npm run tauri android build -- --apk --aab`
4. [ ] Verifikasi:
   ```bash
   apksigner verify --print-certs app-release.apk
   ```
5. [ ] Jika Play Store: aktifkan Play App Signing dan unggah AAB.
6. [ ] Install di Android 14 fisik (lihat B-05).

### F. Definisi selesai B-01

- [ ] `signtool verify` PASS untuk MSI dan NSIS
- [ ] `apksigner verify` PASS untuk APK/AAB
- [ ] Install bersih di Windows 11 + Android 14 (DV-01…DV-20)
- [ ] Kunci tersimpan di secret manager + prosedur rotasi tertulis
- [ ] Bukti (screenshot/log/hash) dilampirkan ke release notes

## B-04 — SMTP Kustom untuk Reset Password

### Fakta konfigurasi saat ini

| Item | Nilai | Bukti |
|---|---|---|
| Alur reset | `resetPasswordForEmail` → `/reset-password` | `src/components/auth/ResetPasswordForm.tsx` |
| Site URL produksi | `https://gerbangedukasi.edukasigerbang.workers.dev` | `.env.production` |
| SMTP | Default Supabase; pernah 429 | riwayat insiden |
| Domain pengirim | Belum ada | — |

### A. Keputusan

- [ ] Vendor SMTP: `Resend` / `SendGrid` / `Postmark` / `SES` (lingkari)
- [ ] Domain pengirim: `no-reply@______________________`
- [ ] Reply-to dukungan: `edukasigerbang@gmail.com` (atau domain resmi)
- [ ] Batas kirim harian yang disepakati: ______________________

### B. DNS (di penyedia domain)

- [ ] SPF: tambahkan include vendor
- [ ] DKIM: pasang record dari vendor, verifikasi status `verified`
- [ ] DMARC: mulai `p=none`, pantau, lalu naikkan bertahap
- [ ] Verifikasi domain di dashboard vendor

### C. Konfigurasi Supabase

1. [ ] Authentication → Settings → SMTP: isi host, port `587`, user, password, sender name/email.
2. [ ] Enable custom SMTP.
3. [ ] Authentication → URL Configuration:
   - Site URL: `https://gerbangedukasi.edukasigerbang.workers.dev`
   - Redirect allowlist: `https://gerbangedukasi.edukasigerbang.workers.dev/reset-password`
   - Redirect dev (opsional): `http://localhost:3000/reset-password`
4. [ ] Template **Reset Password**: pastikan memakai `{{ .ConfirmationURL }}` dan bahasa Indonesia.
5. [ ] (Opsional) naikkan rate limit email setelah domain terverifikasi.

### D. Uji end-to-end

1. [ ] Buka situs produksi → Login → Lupa password.
2. [ ] Kirim ke email uji; pastikan diterima < 2 menit, tidak masuk spam.
3. [ ] Periksa header: `spf=pass`, `dkim=pass`, `dmarc=pass`.
4. [ ] Klik tautan → halaman `/reset-password` terbuka.
5. [ ] Simpan password baru (min 8, maks 72) → login berhasil.
6. [ ] Ulangi 3× cepat: tidak ada 429.
7. [ ] Cek Supabase Auth logs: `user_recovery_requested` dan `user_updated_password`.

### E. Keamanan

- [ ] Kredensial SMTP hanya di dashboard Supabase/secret manager
- [ ] Tidak ada kredensial di repo, log, atau screenshot
- [ ] Prosedur rotasi password SMTP dicatat
- [ ] Template email tidak membocorkan informasi akun

### F. Definisi selesai B-04

- [ ] Email reset diterima di Gmail/Outlook tanpa masuk spam
- [ ] SPF/DKIM/DMARC PASS
- [ ] Reset password end-to-end berhasil di produksi
- [ ] Tidak ada 429 pada pengujian wajar
- [ ] Bukti header + log dilampirkan
